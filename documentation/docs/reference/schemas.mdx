# The published schemas

Every JSON document dep-scan writes has a published JSON Schema: the scan's manifest, findings and evidence records, the doctor report, each verb's output document, and the MCP server's tool inputs and outputs. The schemas are draft 2020-12 documents carried inside the packages, printed by `depscan schema`, so a reader validates against the same definition the writer used instead of guessing from an example.

## The command

```bash
depscan schema                      # list every published schema
depscan schema --format json        # the list with each schema's $id and title
depscan schema finding              # one schema document, on stdout
depscan schema depscan-scan-output  # names are the file names without .json
```

An unknown name is a usage error with the list of known ones. The short name `finding` is accepted as an alias for `depscan-finding`. Every `$id` follows `urn:owasp:depscan:schema:<name>:<version>`, so a consumer can state exactly which version of a contract it read: a schema that embeds another refers to it rather than copying it, and a version bump changes the `$id`, never the meaning of an old document.

## Validating a document

The schemas are ordinary files inside the installed package, so a validator needs no network. From Python, with dep-scan's own helper:

```python
from analysis_lib.findings.schemas import validate, schema_names
import json

with open("reports/depscan.manifest.json") as handle:
    validate("depscan-manifest", json.load(handle))
with open("reports/depscan.findings.json") as handle:
    document = json.load(handle)
for finding in document["findings"]:
    validate("depscan-finding", finding)
print(schema_names())
```

`depscan validate` is the command-line form for CSAF and CycloneDX documents, with the schemas bundled the same way ([the validate page](validate)).
