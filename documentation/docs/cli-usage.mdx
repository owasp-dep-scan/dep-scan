# Usage

dep-scan is ideal for use during continuous integration (CI) and as a local development tool.

## The verbs

The dep-scan 7 command line starts with a verb: `depscan scan`, `depscan vdb`, `depscan serve` and so on. Each verb owns its options, and `depscan <verb> --help` prints them.

| Verb | What it does |
| --- | --- |
| `scan` | Scan a project, BOM, purl or container image for vulnerabilities. |
| `report` | Render the console tables and explanations of a saved scan. |
| `vdb` | Download and inspect the vdb vulnerability database. |
| `doctor` | Report the tools, data and capabilities a scan can use here. |
| `schema` | Print the published finding schemas. |
| `config` | Show the effective scan options or write a config file. |
| `serve` | Run depscan as a server. |
| `validate` | Validate CSAF VEX or CycloneDX VDR/VEX documents against their schema. |
| `version` | Print the dep-scan version, with tool versions as JSON. |
| `help` | Show the top-level help, or one verb's help. |

The table rows are the verbs' own help descriptions. The top-level help lists the same verbs:

```text
usage: depscan [-h]
               {scan,report,vdb,doctor,schema,config,serve,validate,version,help} ...

Fully open-source security and license audit for application dependencies and
container images based on known vulnerabilities and advisories.

positional arguments:
  {scan,report,vdb,doctor,schema,config,serve,validate,version,help}
    scan                Scan a project, BOM, purl or container image for
                        vulnerabilities.
    report              Render the console tables and explanations of a saved
                        scan.
    vdb                 Download and inspect the vdb vulnerability database.
    doctor              Report the tools, data and capabilities a scan can use
                        here.
    schema              Print the published finding schemas.
    config              Show the effective scan options or write a config
                        file.
    serve               Run depscan as a server.
    validate            Validate CSAF VEX or CycloneDX VDR/VEX documents
                        against their schema.
    version             Print the dep-scan version, with tool versions as
                        JSON.
    help                Show the top-level help, or one verb's help.

options:
  -h, --help            show this help message and exit

Visit https://github.com/owasp-dep-scan/dep-scan to learn more
```

                        Additional arguments to pass to cdxgen

                        silently degrading. Passed through to cdxgen so
                        extractor failures fail BOM generation, and applied to
                        blint, rusi, golem, and dosai failures, unreadable
                        reachability reports, empty slices, and empty package

                        Override project types if auto-detection is incorrect.
                        Multiple values supported.
  --private-ns PRIVATE_NS
                        Private namespace to use while performing oss risk
                        audit. Private packages should not be available in
                        public registries by default. Comma separated values
                        accepted.
  --deep                Perform deep scan by passing this --deep argument to
                        cdxgen. Useful while scanning docker images and OS
                        packages.
  --fuzzy-search        Perform fuzzy search by creating variations of package
                        names. Use this when the input SBOM lacks a PURL.
  --search-order {purl,pcu,cpe,cpu,url}
                        Attributes to use while searching for vulnerabilities.
                        Default: PURL, CPE, URL (pcu).
  --severity {low,medium,high,critical}

                        high, critical). Only advisories at or above this
                        severity are returned. depscan applies this floor to
                        the final VDR on any database; on the extended vdb
                        (VDB_INCLUDE_METADATA) it is additionally pushed down
                        into the search for speed. Findings with no rated
                        severity are kept.
  --malware-only        Report only malware advisories (MAL-*). Works on the
                        default vdb because is_malware is always populated via
                        the MAL- fallback.
  --no-universal        Depscan would attempt to perform a single universal
                        scan instead of individual scans per language type.
  --no-vuln-table       Do not print the table with the full list of
                        vulnerabilities. This can help reduce console output.
  --explanation-mode {Endpoints,EndpointsAndReachables,NonReachables,LLMPrompts}
                        Style of explanation needed. Defaults to Endpoints and
                        Reachables.
  --annotate            Include the generated text VDR report as an
                        annotation. Defaults to true when explain is enabled;
                        false otherwise.

  Select which published vdb database the scan downloads. These can also be
  persisted in the depscan config file (e.g. vdb_flavor = "app-only"). An
  explicit VDB_DATABASE_URL env pin always wins. The `depscan vdb download`

                        Default: app+os.
  --vdb-time {2y,default,10y}

  --vdb-extended        Deprecated alias selecting the metadata flavor (app-

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success. |
| 1 | A scan or command that could not run, for example an unusable vulnerability database or a source target that does not exist. |
| 2 | A usage error, including any dep-scan 6 command line (see below). |
| 4 | A requested capability that cannot run, for example a named check whose analyzer is missing, or an iOS or firmware target. |

Findings never change the exit code in this version: a scan that reports vulnerabilities still exits 0, and a clean scan never exits non-zero for being clean.

## Scanning projects locally (Python version)

```bash
sudo npm install -g @cdxgen/cdxgen
# Normal version recommended for most users (MIT)
pip install owasp-depscan

# For a performant version, that uses valkey cache during risk audit (BSD-3-Clause)
pip install owasp-depscan[perf]
```

This would install two commands called `cdxgen` and `depscan`.

You can invoke the scan verb directly with the various options.

```bash
cd <project to scan>
depscan scan $PWD --reports-dir $PWD/reports
```

With no target at all, `depscan scan` scans the current directory.

## Target detection

The scan verb takes what to scan as positional targets, and detects each target's kind: a source directory, git URL, container image reference or archive, BOM file, BOM directory, purl, binary or app package.

| Kind | Detected as | What the scan uses |
| --- | --- | --- |
| `purl` | a string starting with `pkg:` | the purl search |
| `git` | a git URL (`http://`, `https://`, `git://`, `ssh://` or `git@`) that does not end in an archive extension | the remote source |
| `container` | an image reference (`name:tag`, `registry/name` or `name@sha256:<digest>`), a `.tar` or `.tar.gz` archive file, or a directory holding an `oci-layout` file | the container image |
| `bom` | an existing JSON file whose document is a CycloneDX BOM | that BOM |
| `bom-dir` | an existing directory whose JSON files are all CycloneDX documents | every BOM in the directory |
| `binary` | an existing executable file that is not a BOM | blint binary analysis |
| `android` | an existing `.apk` or `.aab` file | blint app analysis |
| `ios` | an existing `.ipa` file | refused (see below) |
| `source` | an existing path no more specific kind names, or any other string | the source tree |

An existing path beats a same-shaped image reference: a string that is both a possible image reference and an existing path is scanned as the path, whatever kind the path itself gives.

`--target-kind KIND` forces the kind of every target instead of detecting it. `ios` and `firmware` have no inventory path in this version: naming either (or scanning a `.ipa` file) stops the scan with exit 4 and the reason on stderr. A `source` target that does not exist is refused with exit 1. Detection logs, on stderr, the kind chosen for each target and the evidence behind it.

When the user passed no `-t`, the kind names the project type too: a `container` target scans as `docker`, a `binary` target as `binary` and an `android` target as `apk`.

## The checks

`--checks` takes a comma-separated list of check names: `all`, `vulnerabilities`, `reachability`, `license`, `supply-chain`, `binary`, `memory-safety`, `mobile`, `code`, `crypto`.

| Check | What it maps onto | Capability gate |
| --- | --- | --- |
| `vulnerabilities` | vulnerability matching, including the malware advisory reporting | none: always assessed |
| `reachability` | keeps the reachability analyzers on | `reachability` |
| `license` | appends the `license` pseudo type, which triggers the license analysis | `license` |
| `supply-chain` | the package risk audit | `supply-chain` |
| `binary` | adds the `binary-analysis` technique, which scans through blint | `binary` (needs the blint package) |
| `memory-safety` | not implemented in this version | exits 4 when named explicitly |
| `mobile` | not implemented in this version | exits 4 when named explicitly |
| `code` | not implemented in this version | exits 4 when named explicitly |
| `crypto` | not implemented in this version | exits 4 when named explicitly |

An explicit `--checks` list defines the whole optional set: checks not named are off, so `--checks vulnerabilities` turns reachability off (the v6 equivalent was `--reachability-analyzer off`). The `vulnerabilities` check always runs, named or not. A check named explicitly whose capability cannot run on the machine stops the scan with exit 4 before any work, printing the doctor's reason on stderr. `--checks all` selects every check whose capability is available, turns the unavailable ones off, and records each of them in the manifest as a `check-<name>` stage with status `not-assessed` and the doctor's reason.

Without `--checks` and without `--profile` the set is `vulnerabilities,reachability`, the v6 default, and it is never gated.

## The profiles

`--profile` names one of five scan profiles. Each sets a check set and analyzer settings; an explicitly passed option always wins over the profile, so `--profile quick --reachability-analyzer FrameworkReachability` keeps framework reachability on.

| Profile | Checks | Other settings |
| --- | --- | --- |
| `quick` | `vulnerabilities` | reachability off |
| `ci` | `vulnerabilities,reachability` | explanations off, so no LLM prompt file is ever written |
| `deep` | `vulnerabilities,reachability,license,supply-chain` | semantic reachability (`SemanticReachability`) |
| `research` | `deep` plus cdxgen's research BOM profile | `--bom-profile research` implied |
| `offline` | `vulnerabilities,reachability` | no database download, local cdxgen only, golem offline, no risk audit |

## BOM profiles and excluded types

`--bom-profile` is cdxgen's own BOM profile flag (`appsec`, `research`, `operational`, `threat-modeling`, `license-compliance` and the machine-learning profiles), the option v6 called `--profile`. It shapes the BOM cdxgen generates; the v7 `--profile` (above) shapes the scan instead.

`--exclude-type` drops a project type from the detected list before any stage runs, so no inventory or scan runs for it: excluding `os` or `docker` stops the OS and container scans. The type is also passed to cdxgen as a repeated `--exclude-type` argument, so the BOM contents are filtered the same way. The option is repeatable and accepts comma-separated values.

```bash
depscan scan . --exclude-type os --exclude-type docker
```

## JSON output

`--format json` (on `scan` and every other verb that renders) prints one JSON document on stdout and moves the banner, tables, progress and logs to stderr, so `depscan scan . --format json | jq` sees exactly the document.

The scan verb prints `{"scanDir", "manifest", "findings"}` per target: the reports directory, the manifest the scan wrote and the findings array. Several targets print an array of those objects, one per target in the order given. A target the detection refused gets a `{"target", "error"}` entry carrying the reason, so no target is silently dropped.

```bash
depscan scan . --format json
```

## Several targets

Passing more than one target runs one scan per target, each writing into `<reports-dir>/<n>-<name>/`, where `n` is the target's 1-based position and `<name>` its basename for an existing path, or the reference with `/`, `\`, `:` and `@` replaced by `-` (truncated to 60 characters) for a purl, URL or image reference. The exit code is the highest of the scans.

```bash
depscan scan app/src app/bom.json --reports-dir reports
```

Zero or one target uses `--reports-dir` as given.

## dep-scan 6 command lines are refused

A command line that starts with an option, as every dep-scan 6 invocation did, is not run. dep-scan translates it, prints the equivalent v7 command and a link to the migration guide on stderr, and exits 2.

```text
$ depscan --src .
depscan: this is a dep-scan 6 command line, which dep-scan 7 no longer runs.
The equivalent v7 command is: depscan scan .
See the migration guide: https://depscan.readthedocs.io/migrate-v6-to-v7/
```

Bare `depscan` is a usage error too; use `depscan scan` to scan the current directory. `depscan -h` and `depscan --help` still print the help and exit 0.

## Scanning containers locally (Python version)

Scan a Java project.

```bash
depscan scan <path> -o containertests -t java
```

Scan `latest` tag of the container `shiftleft/scan-slim`. The reference is detected as a container target and scanned as the `docker` type.

```bash
depscan scan shiftleft/scan-slim -o containertests
```

Include `license` to the type to perform the license audit.

```bash
depscan scan shiftleft/scan-slim -o containertests -t docker,license
```

You can also specify the image using the sha256 digest

```bash
depscan scan redmine@sha256:a5c5f8a64a0d9a436a0a6941bc3fb156be0c89996add834fe33b66ebeed2439e -o containertests
```

You can also save container images using docker or podman save command and pass the archive to depscan for scanning.

```bash
docker save -o /tmp/scanslim.tar shiftleft/scan-slim:latest
# podman save --format oci-archive -o /tmp/scanslim.tar shiftleft/scan-slim:latest
depscan scan /tmp/scanslim.tar -o reports
```

Refer to the docker tests under the GitHub action workflow for this repo for more examples.

## Scanning projects locally (Docker container)

`ghcr.io/owasp-dep-scan/dep-scan` container image can be used to perform the scan.

To scan with default settings

```bash
docker run --rm -v $PWD:/app ghcr.io/owasp-dep-scan/dep-scan depscan scan /app --reports-dir /app/reports
```

To scan with custom environment variables based configuration

```bash
docker run --rm \
    -e VDB_HOME=/db \
    -e GITHUB_TOKEN=<token> \
    -v /tmp:/db \
    -v $PWD:/app ghcr.io/owasp-dep-scan/dep-scan depscan scan /app --reports-dir /app/reports
```

In the above example, `/tmp` is mounted as `/db` into the container. This directory is then specified as `VDB_HOME` for caching the vulnerability information. This way the database can be cached and reused to improve performance.

> [!IMPORTANT]
> Binding dep-scan to a non-local address is authenticated by default. Set `DEPSCAN_SERVER_API_KEY` before using `depscan serve --server-host 0.0.0.0`, or explicitly opt out with `DEPSCAN_SERVER_ALLOW_UNAUTHENTICATED_BIND=true` only for trusted development environments.

## Specify the BOM engine (Python version)

depscan allows you to customize the BOM generator engine. The supported values are: `auto`, `CdxgenGenerator`, `CdxgenServerGenerator`, `CdxgenImageBasedGenerator`, and `BlintGenerator`.

- **auto**: Uses the container-image-based cdxgen generator (`CdxgenImageBasedGenerator`) if the Docker command is available and the project type specified is not an oci image type (such as docker, podman, and oci). Otherwise, it uses the local cdxgen CLI via `CdxgenGenerator` or the local cdxgen server `CdxgenServerGenerator` if you pass the `--cdxgen-server` argument.
- **CdxgenGenerator**: Always uses the local cdxgen CLI. Install cdxgen using the npm command or download the standalone executable.
- **CdxgenServerGenerator**: Uses the cdxgen server. Specify the URL using the `--cdxgen-server` argument.
- **CdxgenImageBasedGenerator**: Generates a BOM using the official cdxgen container images. You can customize the image name using `CDXGEN_IMAGE_{project_type}` and `CDXGEN_IMAGE_VERSION`. Container image-based generation is more suitable for enterprise applications that require specific build tools and OS libraries for successful BOM generation. This approach is resource-intensive but typically has a higher success rate.
- **BlintGenerator**: Uses the optional OWASP [blint](https://github.com/owasp-dep-scan/blint) library. This requires installing depscan with all optional packages:
    ```bash
    pip install owasp-depscan[all]
    ```

### Customize cdxgen container image

Container images used by `CdxgenImageBasedGenerator` can be customized using environment variables prefixed with CDXGEN*IMAGE*. For example, to use a custom cdxgen image for Java, set the environment variable `CDXGEN_IMAGE_JAVA`.

## Specify the Vulnerability Analyzer

depscan supports customizing the vulnerability analyzer engine. The supported values are: `auto`, `VDRAnalyzer`, and `LifecycleAnalyzer`.

- **auto**: Uses LifecycleAnalyzer when the target is a BOM directory containing multiple xBOMs; otherwise, it defaults to VDRAnalyzer.
- **VDRAnalyzer**: Mimics the analysis performed by depscan v5 by focusing on a single xBOM and a single BOM lifecycle phase.
- **LifecycleAnalyzer**: Optimized for analyzing multiple phases of a BOM lifecycle, such as pre-build, build, post-build, and operations, to support better prioritization.

The `LifecycleAnalyzer` works by repeatedly invoking cdxgen (for pre-build, build, and container phases) and blint (for post-build) to generate multiple SBOMs. With this rich context, depscan can suppress more false positives and more accurately identify high-priority CVEs. Use the environment variable `DEPSCAN_SOURCE_IMAGE` to specify the image for container SBOM generation.

## Configuration File support

You can pass CLI options to depscan using a configuration file with the `depscan scan --config` argument. By default, depscan looks for `.config/depscan.toml` in the current directory. A sample file named `depscan.toml.sample` is also generated in the reports directory (Specified via `--reports-dir`). Customize this file as needed and copy it to the `.config` directory to run depscan without specifying arguments each time.

`depscan config show` prints every scan option with its value and where the value came from (the command line, `depscan.toml`, an environment variable or the default), and `depscan config init` writes the effective options to `./depscan.toml`.

## The other verbs

```bash
# Run dep-scan as a server (the --server-* options live here; there is no --config on serve)
depscan serve --server-host 127.0.0.1 --server-port 7070

# Download or inspect the vulnerability database
depscan vdb download --flavor app-only

# Validate a VDR, VEX or CSAF document against its schema
depscan validate reports/sbom-build.vdr.json

# Print the published finding schemas
depscan schema finding

# Print the version, plus every tool version as JSON
depscan version --format json

# Show every scan option with its value and where it came from
depscan config show --reports-dir reports
```

`depscan doctor` reports the tools, database and capabilities a scan can use on this machine, and `depscan report` re-renders a saved scan directory. Both have their own pages: [depscan doctor](doctor) and [the scan directory](output/scan-directory).

## Vulnerability database management (depscan vdb)

The `depscan vdb` command selects, downloads, and inspects any published vdb image variant. See the [vulnerability database guide](/vulnerability-database) for the full image matrix.

```bash
# Default full (app+OS) flavor
depscan vdb download

# Smaller app-only flavor
depscan vdb download --flavor app-only

# Extended flavor (for severity and metadata search)
depscan vdb download --flavor app-extended

# Type shards for a scoped workload
depscan vdb download --shards pypi npm
```

`depscan vdb info` prints the local database and shard store state, and `depscan vdb path` prints the `VDB_HOME` directory. The deprecated `--scope`/`--time`/`--extended` aliases still work on `download` with a warning naming the flavor they resolve to. There is no per-distro database on the v7 line; `--distro` is rejected with the five flavors listed.
