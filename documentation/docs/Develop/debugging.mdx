# Debugging a scan

Most scan questions are answered before a debugger is needed: `SCAN_DEBUG_MODE=debug` turns on the full log surface, including each tool invocation, the reports the adapters looked for and the reasons a stage or analyzer did not run. The doctor report answers the same question about the machine. This page covers the two debugger setups and the two log sources.

## The logs

A scan writes two streams, and knowing which is which settles half the confusion: results and JSON go to stdout, and every log line, warning and progress display goes to stderr. Run a scan with stderr visible and `SCAN_DEBUG_MODE=debug`:

```bash
SCAN_DEBUG_MODE=debug uv run depscan scan ./my-project --reports-dir reports --debug
```

## Visual Studio Code and debugpy

A `launch.json` configuration runs the CLI in the debugger:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug depscan CLI",
      "type": "debugpy",
      "request": "launch",
      "env": {
        "SCAN_DEBUG_MODE": "debug"
      },
      "module": "depscan.cli",
      "console": "integratedTerminal",
      "args": [
        "scan",
        "/work/project",
        "--reports-dir",
        "/work/reports"
      ]
    }
  ]
}
```

Set a breakpoint in `depscan/lib/pipeline.py` for the scan stages, in `depscan/lib/bom.py` for BOM generation and the analyzer runners, and in the adapter under `packages/analysis-lib/src/analysis_lib/evidence/adapters/` for how a producer's report becomes records.

## PyCharm

Open the repository, select the `.venv` interpreter that `uv sync` created, and add a run configuration of module `depscan.cli` with the same arguments as above; the entry point is `depscan/cli.py` and the verb registry builds the parser in `depscan/commands/__init__.py`.

## When a tool misbehaves, not dep-scan

The analyzers are separate processes. To see what one of them was given and what it answered, the debug log prints the command line, and the raw reports stay in the scan directory under `analysis/<tool>/` (or as the `*-semantics.slices.json` files cdxgen wrote), which is the input the adapter actually read. Re-running the tool's command by hand reproduces its side of the conversation.
