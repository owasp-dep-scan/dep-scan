# Lesson 7: CI gating

This lesson is the CI job in miniature: a scan with the CI profile, the exit codes, the JSON contract, and a gate on the findings file that reads the coverage block so an unassessed finding cannot pass as a clean one. The scan target is a pinned package URL, so the lesson runs in seconds and shows the shape without a project's noise; the [CI page](../integrate/ci) is the workflow around it.

The inputs are pinned: `pkg:pypi/requests@2.31.0`, dep-scan 7.0.0a3 and the `app-only` database flavor. The output below is from a run on 2026-11-25. One deliberate negative case is included: a refused capability, because a gate that never saw a failure is not a gate.

## The script

The commands live in `documentation/lessons/07-ci-gating/run.sh` (and `expect.txt` beside it holds the output lines the lesson's CI job greps for). The page embeds the script verbatim, so the page and the script cannot differ:

```bash
#!/usr/bin/env bash
# Lesson 07: CI gating with a profile, the exit codes and a findings gate.
#
# Runs the CI profile over a pinned package URL, shows the exit code and the
# JSON output contract, and gates on the findings file the way the CI page
# does, reading the coverage block so an unassessed finding cannot pass as a
# clean one.
#
# Needs: dep-scan and an app-only vulnerability database. The scan itself is
# a package URL search, so it is fast and needs no project.
set -euo pipefail

WORK="${WORK:-/tmp/depscan-lesson-07}"
SCANS="$WORK/scans"
mkdir -p "$SCANS"

### Scan with the CI profile
set +e
depscan scan pkg:pypi/requests@2.31.0 --profile ci --vdb-flavor app-only \
  --format json --no-banner -o "$SCANS/reports" > "$SCANS/scan.json"
rc=$?
set -e
echo "scan exit code: $rc"

### The JSON contract: stdout is exactly one document
python3 - "$SCANS" <<'PY'
import json, sys
d = sys.argv[1]
doc = json.load(open(f"{d}/scan.json"))
entry = doc["scans"][0]
print(f"one document, scans: {len(doc['scans'])}")
print(f"target kind: {entry['kind']}")
print(f"findings in the entry: {len(entry['findings'])}")
PY

### Gate on the findings file, coverage included
python3 - "$SCANS/reports" <<'PY'
import json, sys
d = sys.argv[1]
f = json.load(open(f"{d}/depscan.findings.json"))
critical = [x for x in f["findings"]
            if x["severity"] == "critical" and x["coverage"]["state"] == "assessed"]
print(f"assessed critical findings: {len(critical)}")
allfindings = len(f["findings"])
not_assessed = [x for x in f["findings"] if x["coverage"]["state"] == "not_assessed"]
print(f"findings total: {allfindings}, not assessed: {len(not_assessed)}")
PY

### What a failing scan looks like
# A requested capability that cannot run exits 4; the error document is on
# stdout in json format.
set +e
depscan scan pkg:pypi/requests@2.31.0 --checks memory-safety --format json \
  --no-banner -o "$SCANS/refused" > "$SCANS/refused.json" 2>/dev/null
rc=$?
echo "refused scan exit code: $rc"
python3 -c "
import json
doc = json.load(open('$SCANS/refused.json'))
print('error verb:', doc['error']['verb'], 'exitCode:', doc['error']['exitCode'])
"
set -e
```

## Reading the run

The scan exits 0 (findings never change the exit code in this version), and stdout is exactly one JSON document:

```text
scan exit code: 0
one document, scans: 1
target kind: purl
findings in the entry: 3
```

The gate reads the findings file the way the CI page's `jq` does, and the coverage filter is the part that keeps it honest:

```text
assessed critical findings: 0
findings total: 3, not assessed: 0
```

A critical finding whose deciding analysis never ran carries `coverage.state: not_assessed` with the reason, and the gate counts it apart from the assessed ones. The negative case shows the other half of the contract: a requested capability that cannot run is exit code 4, and in json format the error document is on stdout, so the job that asked for it parses the refusal like any other document:

```text
refused scan exit code: 4
error verb: scan exitCode: 4
```

What this lesson does not show is dep-scan failing the build because findings exist. There is no policy gate in this version: exit 0 means the scan ran, not that everything is fine, and the honest gate is the workflow's own step over the findings file, coverage included. The policy gate with its own exit code is [planned work](https://github.com/owasp-dep-scan/dep-scan/issues/594), and this lesson's gate is the shape it will replace.

## Takeaways

- `--profile ci` is the CI-shaped scan, and `--fail-on-error` is how a degraded scan refuses to pass as clean.
- Exit code 0 means the scan ran; the gate is yours, over the findings file.
- The coverage block belongs in every gate condition, or an unassessed finding passes as clean.
