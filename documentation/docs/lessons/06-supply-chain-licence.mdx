# Lesson 6: a supply-chain and licence audit

This lesson runs the supply-chain and licence checks over the same pinned Juice Shop commit as lesson 1 and reads the two reports they write. Neither check needs anything beyond cdxgen and the network a registry lookup uses, and both write plain JSON arrays into the scan directory, so the audit is a file a reviewer opens, not console output to scrape.

The inputs are pinned: Juice Shop at commit `33518f5a0911`, dep-scan 7.0.0a3 with cdxgen 13.9.0, the `app-only` database flavor, and the npm and PyPI registries the risk audit queries.

## The script

The commands live in `documentation/lessons/06-supply-chain-licence/run.sh` (and `expect.txt` beside it holds the output lines the lesson's CI job greps for). The page embeds the script verbatim, so the page and the script cannot differ:

```bash
#!/usr/bin/env bash
# Lesson 06: a supply-chain and licence audit.
#
# Runs the supply-chain and licence checks over the same pinned Juice Shop
# commit as lesson 01, and reads the risk report, the licence report and the
# manifest stages that record what ran.
#
# Needs: dep-scan, cdxgen, Node.js, and an app-only vulnerability database.
set -euo pipefail

WORK="${WORK:-/tmp/depscan-lesson-06}"
SRC="$WORK/juice-shop"
SCANS="$WORK/scans"
COMMIT=33518f5a0911e25d9df747b1e70fb7af279a755c
mkdir -p "$SCANS"

### Pin the project
if [ ! -d "$SRC/.git" ]; then
  git clone --quiet https://github.com/juice-shop/juice-shop.git "$SRC"
fi
git -C "$SRC" checkout --quiet $COMMIT
echo "project: juice-shop $COMMIT"

### Run the supply-chain and licence checks
depscan scan "$SRC" --checks supply-chain,license --no-banner \
  --cdxgen-args "--exclude 'Dockerfile' --exclude 'docker-compose*.yml'" \
  -o "$SCANS/reports"

### What ran, in the manifest's own words
python3 - "$SCANS/reports" <<'PY'
import json, sys
d = sys.argv[1]
m = json.load(open(f"{d}/depscan.manifest.json"))
for s in m["stages"]:
    if s["name"] in ("licenses", "risk"):
        print(f"stage {s['name']}: {s['status']}")
PY

### Read the risk report
# One JSON array of row objects with plain values; a score crossing the
# ceiling prints as a console table, and every audited package is a row.
python3 - "$SCANS/reports" <<'PY'
import json, sys
d = sys.argv[1]
rows = json.load(open(f"{d}/depscan-risk-universal.json"))
print(f"audited packages: {len(rows)}")
flagged = [r for r in rows if r["Risk Score"] >= 4]
print(f"rows at or above the ceiling of 4: {len(flagged)}")
with_risks = [r for r in rows if r["Identified Risks"]]
x = with_risks[0]
print(f"row shape: Package, Used?, Risk Score, Identified Risks ({len(x['Identified Risks'])} entries)")
PY

### Read the licence report
python3 - "$SCANS/reports" <<'PY'
import json, sys
d = sys.argv[1]
rows = json.load(open(f"{d}/license-universal.json"))
print(f"licence rows: {len(rows)}")
copyleft = [r for r in rows if "Same License" in r.get("License conditions", "")]
print(f"copyleft conditions flagged: {len(copyleft)}")
PY
```

## Reading the run

The manifest names the two stages the checks add, beside the matching every scan does:

```text
project: juice-shop 33518f5a0911e25d9df747b1e70fb7af279a755c
stage licenses: completed
stage risk: completed
audited packages: 382
rows at or above the ceiling of 4: 0
row shape: Package, Used?, Risk Score, Identified Risks (2 entries)
licence rows: 5
copyleft conditions flagged: 2
```

The risk report holds one row per audited package, and a row is plain JSON: the package, whether the scan's code uses it, a numeric score, and the identified risks as a list. Juice Shop's audit on the recorded run flags none at or above the ceiling, which is a finding too: the audit's output is the whole ranked list in `depscan-risk-universal.json`, and the table is only its top. The private-namespace check (`--private-ns`) is the same audit aimed at dependency confusion; name the namespaces your organisation registers and the audit flags any that appear in public.

The licence report is deliberately small on this project: five rows resolved to licence ids with conditions, two of them copyleft. Packages whose BOM carries no licence data are counted on the manifest's licenses stage as never assessed rather than silently clean. A licence policy gate (allowed and denied lists in the config, violations as findings) is planned work; today the file is the audit, read the way you would read a spreadsheet.

## Takeaways

- `--checks supply-chain,license` adds two stages and two plain JSON reports to the scan directory.
- The risk score is a ranking, and the whole ranked list is in the file, not only the rows that cross the ceiling.
- Missing licence data is counted as not assessed on the manifest, never folded into clean.
